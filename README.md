# Agentic Development System

An orchestrator-managed ecosystem of specialised agents that covers the
**entire** software development lifecycle — from raw stakeholder input
through PRD, technical spec, sprint plan, code, tests, accessibility &
performance audits, security, docs, and deployment — and works across
**Claude Code**, **Cursor**, **Google Antigravity**, and **OpenAI Codex**.

Source-of-truth lives in `agents/`, `skills/`, `commands/`, `hooks/` at
the repo root. Per-tool artifacts under `platforms/<tool>/` are
auto-generated by `scripts/sync-platforms.sh`.

## Quickstart

```bash
# Once per machine — install Caveman (output compression).
./scripts/install-caveman.sh

# Once per project — emit native adapters for all supported tools.
./scripts/sync-platforms.sh

# Initialise the orchestrator (creates logs/).
python3 -m orchestrator.cli init

# Validate the registry.
python3 -m orchestrator.cli validate

# Kick off a full product lifecycle inside your AI tool:
#   /start-product "Build a TODO API with OAuth login"
```

The host AI tool (Claude Code, Cursor, Antigravity, Codex) reads the
adapter files generated under `platforms/<tool>/` and routes the command
through the appropriate agents. The orchestrator can also drive the flow
externally via its Python API.

## Core principles

1. **Single Responsibility** — one skill = one task; one agent = one role.
2. **Plan before execute** — no step runs without a persisted plan.
3. **Spec cascade** — PRD → TSD → sprints → tasks → code. Coding agents
   implement the TSD verbatim.
4. **Confidence gating** — <0.85 (or <0.95 for reviewers/auditors) →
   human-in-loop.
5. **Sensitive surface gating** — secrets, infra, migrations, spec docs
   are always human-gated regardless of confidence.
6. **Test pairing** — every implementation step has a matching test step.
7. **Audit everything** — every action stamped with hashes + confidence
   + timing.
8. **Tech agnostic** — no language assumption; stack detected per project.
9. **Multi-platform** — one source of truth compiles to four host shapes.
10. **Caveman by default** — output compression auto-activates per session.

## Agents

### LLM agents (20)

| Agent | Role |
|---|---|
| `requirements` | Capture raw user stories (lightweight intake) |
| `prd-author` | Write PRD section-by-section |
| `prd-reviewer` | Gap-check the PRD |
| `architect` | Tech stack + components + data model |
| `tech-spec-author` | Write the TSD — the contract coding agents implement |
| `tech-spec-reviewer` | Verify the TSD is implementable as written |
| `sprint-planner` | PRD → epics → stories → estimates → sprints |
| `sprint-reviewer` | Gap-check the sprint plan |
| `planner` | Per-sprint task decomposition (one plan per sprint) |
| `designer` | UI/UX taste, anti-slop, interaction states, copy |
| `frontend` | UI implementation (components, pages, client) |
| `backend` | Server implementation (endpoints, services, data, migrations) |
| `tester` | Unit + Puppeteer E2E generation + execution |
| `reviewer` | Independent code review (correctness, simplicity) |
| `security` | Static + secret + dependency scans (floor 0.95) |
| `accessibility-auditor` | WCAG 2.2 AA conformance (floor 0.95) |
| `performance-auditor` | Bundle / render / network / CWV (floor 0.95) |
| `docs` | READMEs, API docs, changelogs |
| `devops` | Build + CI/CD config |
| `deployer` | Promote artifacts to environments (always human-gated) |

(20 LLM agents total; full list via `python3 -m orchestrator.cli list-agents`.)

### Infra agents (6, deterministic)

Each backs the orchestrator's plumbing. No LLM involved.

| Agent | What it does | Python body |
|---|---|---|
| `infra-router` | Ownership check + dispatch to LLM or infra | `orchestrator/infra/router.py` |
| `infra-logger` | Append-only audit + plan persistence | `orchestrator/infra/logger.py` |
| `infra-confidence` | Floor + sensitive-surface gate | `orchestrator/infra/confidence.py` |
| `infra-stack-detector` | File-sniffing tech stack detection | `orchestrator/infra/stack_detector.py` |
| `infra-registry` | agent + skill lookup | `orchestrator/infra/registry.py` |
| `infra-planner` | Plan invariants + topological order | `orchestrator/infra/planner.py` |

## Hooks

`hooks/*.sh` — lifecycle scripts wired into each platform.

| Hook | When it fires | Exit codes |
|---|---|---|
| `session-start-caveman.sh` | session start | 0 always (fails open) |
| `pre-task-plan.sh` | before any task | 0 ok / 1 no plan / 2 plan missing |
| `confidence-gate.sh` | after agent response | 0 ok / 3 below floor |
| `post-task-log.sh` | after any task | 0 always |
| `post-edit-test.sh` | after a code edit | 0 ok / 4 no paired test |
| `pre-commit-test.sh` | before `git commit` | 0 ok / non-zero on test fail |
| `pre-deploy-check.sh` | before `deploy-environment` | 5 sec-scan / 6 tests not ok |

## The orchestrator

Thin Python coordinator (~60 lines of real logic). The orchestrator's
only contract:

```python
orc.invoke(agent_id, skill_id, inputs) -> {outputs, confidence, touched_paths}
```

If `agent_id` starts with `infra-`, it dispatches to a Python `handle()`
function in `orchestrator/infra/<mod>.py`. Otherwise it calls the
`llm_adapter` callable (the host's runtime — Claude Code, Cursor,
Antigravity, Codex).

The orchestrator does no routing, no logging, no gating, no plan-building
of its own — each of those is owned by an infra agent. See `ARCHITECTURE.md`
for the full picture.

## Platform adapters

One source of truth → four shapes. `scripts/sync-platforms.sh` is the
compiler.

| Source | Claude Code | Cursor | Antigravity | Codex |
|---|---|---|---|---|
| `agents/*.md` | `.claude/agents/*.md` | `.cursor/rules/agents/*.mdc` | `.antigravity/agents/*.yaml` | section in `AGENTS.md` |
| `skills/**/SKILL.md` | `.claude/skills/<id>/SKILL.md` | `.cursor/rules/skills/<id>.mdc` | `.antigravity/skills/<id>.yaml` | section in `AGENTS.md` |
| `commands/*.md` | `.claude/commands/*.md` | `.cursor/commands/*.md` | `.antigravity/commands/*.yaml` | — |
| `hooks/*.sh` | `.claude/hooks/` + `settings.json` | `.cursor/hooks/` | `.antigravity/hooks/` + `config.yaml` | git hooks (manual) |

Each platform has a `platforms/<tool>/README.md` with install + wiring
details.

## Caveman integration

[Caveman](https://github.com/juliusbrussee/caveman) compresses LLM output
by ~65% on average while preserving accuracy.

- Install once: `scripts/install-caveman.sh`.
- Auto-activates on **Claude Code** and **Codex** (Caveman's built-in
  list).
- For **Cursor**, `caveman --with-init` writes rule files that Cursor
  auto-loads.
- For **Antigravity**, run `/caveman full` per session, or wire
  `hooks/session-start-caveman.sh` into `config.yaml`'s `lifecycle.pre_task`.

Mode (`lite|full|ultra|wenyan`) is configurable via `ADS_CAVEMAN_MODE`
env var. `CAVEMAN_STATUSLINE_SAVINGS=0` is set by default to keep CI logs
clean.

## Confidence gating

Every agent emits a `confidence ∈ [0.0, 1.0]`. Below floor →
escalation prompt to the human.

| Floor | Agents |
|---|---|
| 0.85 (default) | most LLM agents |
| 0.95 | `prd-reviewer`, `tech-spec-reviewer`, `sprint-reviewer`, `security`, `accessibility-auditor`, `performance-auditor`, `deployer` |

**Sensitive surfaces are always human-gated** regardless of confidence:
see `SPEC.md` §4.

## Audit logs

Every step writes one JSON record to `logs/audit/<YYYY-MM-DD>.jsonl`:

```json
{ "ts": "...", "plan_id": "...", "step_id": "...",
  "agent": "...", "skill": "...",
  "inputs_sha256": "...", "outputs_sha256": "...",
  "confidence": 0.93, "result": "ok|escalated|failed",
  "human_input": null, "duration_ms": 1234 }
```

Plans live at `logs/plans/<uuid>.json`. `logs/` is gitignored by default.

## Test pairing invariant

`infra-planner.enforce-test-pairing` refuses any plan where a
`frontend`/`backend` step lacks a paired `testing` step. The
`post-edit-test.sh` hook enforces the same rule at runtime: editing a
code file without a matching test reference triggers an immediate
test-generation step before the next edit.
