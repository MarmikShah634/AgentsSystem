# System Specification (general)

This file is binding for every agent in the Agentic Development System,
regardless of host (Claude Code, Cursor, Antigravity, Codex). Per-tool
files (`CLAUDE.md`, `CURSOR.md`, `ANTIGRAVITY.md`, `CODEX.md`) layer on
host-specific operational notes; they never override the rules below.

## 1. Single Responsibility Principle

- **One skill, one task.** A skill must do exactly one observable thing.
- **One agent, one role.** Agents do not borrow each other's skills.
  Cross-agent calls go through `infra-router`.
- **No multi-skill files.** A skill SKILL.md never bundles two tasks.

## 2. Plan-First

- No task executes without a written plan persisted at
  `logs/plans/<uuid>.json`.
- The `infra-planner` agent's `enforce-test-pairing` skill refuses plans
  where any `frontend`/`backend` step lacks a paired `testing` step.
- Plans are immutable. Re-planning produces a new plan id.

## 3. Confidence Gating

- Every agent response carries a `confidence` in `[0.0, 1.0]`.
- `infra-confidence` evaluates against a floor (default **0.90**;
  reviewers and auditors raise to **0.95**).
- Below floor → escalate to human via the human responder.

## 4. Sensitive-Surface Gating

The following globs are **always** human-gated regardless of confidence:

- `secrets/**`, `infra/**`, `migrations/**`
- `**/.env*`, `**/Dockerfile`, `**/*.tf`
- `**/openapi.yaml`, `**/openapi.yml`
- `docs/prd/**`, `docs/tsd/**`, `docs/sprints/**`

## 5. Spec Cascade

Coding agents (`frontend`, `backend`) implement against the TSD verbatim.
The TSD is derived from the PRD; the PRD is derived from stakeholder input
via `requirements` → `prd-author`. Every deviation from a spec requires a
re-review (`prd-reviewer` → `tech-spec-reviewer`).

## 6. Test Pairing

- Every implementation step has a paired test step.
- The `post-edit-test.sh` hook fails closed if an edited code file has no
  corresponding test reference in the repo.
- Tests use the project's native runner — never invented.

## 7. Audit Trail

- Every step writes a JSON record to `logs/audit/<date>.jsonl` with
  `inputs_sha256`, `outputs_sha256`, `confidence`, `duration_ms`,
  `result`.
- Records are append-only; never edit history.

## 8. Caveman Default

Output compression via [Caveman](https://github.com/juliusbrussee/caveman)
is enabled by default. `hooks/session-start-caveman.sh` activates it; for
hosts without a session-start hook, the rule files generated by
`caveman --with-init` are copied into the host's config directory.

## 9. Tech Agnosticism

No agent assumes a language or framework. Stack detection is delegated to
`infra-stack-detector`. Skills delegate language-specific work to the
host runtime, passing only structured prompts.

## 10. Logs Belong to Runs, Not Repos

`logs/` is gitignored. Remove the gitignore rule if you want runs
tracked.

## 11. Reading Order for New Agents

1. This file (`SPEC.md`)
2. The host-specific file (`CLAUDE.md` / `CURSOR.md` / `ANTIGRAVITY.md` /
   `CODEX.md`)
3. The agent's own spec under `agents/<id>.md`
4. The current plan under `logs/plans/<id>.json`
5. The skill's `SKILL.md` for the step being executed
